# 06 · Roadmap

Cada hito se itera dos veces (propuesta y solución) y se cierra con tests en verde.

| Hito | Contenido |
|---|---|
| **M0 · Cimientos** ✅ | Monorepo con npm workspaces, TypeScript estricto, Vitest, ESLint, `spec:check` |
| **M1 · Dominio** ✅ | Validación, Event Bus, Orchestrator (paralelismo, router, bucles, subdiagramas, pausa/cancelación, presupuesto, reintentos, preguntas de agentes, logs con redacción), `MockAgent`: 87 tests |
| **M2 · Persistencia y logs** ✅ | Store JSON versionado con migraciones y respaldo, escritura atómica, `events.jsonl` + `meta.json` por ejecución, listado, retención, runs interrumpidos (SPEC-010, R8.8–R8.13); sin SQLite por ahora |
| **M3 · UI editor** ✅ | Modelo del editor (`packages/editor`), interfaz React Flow (`packages/ui`), cáscara Electron segura con IPC validado (`apps/desktop`); SPEC-014 y SPEC-019 (M3). Pendiente de comprobar a mano: arrancar con `npm run start:desktop` |
| **M3b · Espacios de trabajo** ✅ (gestor) | WorkspaceManager: aislamiento por agente, fusión, conflictos e instantáneas por iteración |
| **M3c · Subdiagramas** | Nodo `subdiagram` por referencia a plantilla, nodo `output`, validaciones (ciclos, profundidad), agrupar nodos en plantilla |
| **M4 · Ejecución en vivo** ✅ | `packages/runtime` (RunService, lotes de 50 ms, demo), IPC de ejecución, cliente con dedupe por `seq`, vista en vivo sobre el lienzo, panel del nodo con chat, visor de logs y panel de resultados. **M4b** (pendiente): nodos compuestos colapsados, notificación de escritorio, comparar ejecuciones, previsualizar imágenes/audio, instantáneas comparables, pausa por nodo; el motor de permisos pasa a M6; el replay a M7. Integrar el gestor de espacios con el orquestador llega con el adapter real (M6) |
| **M4c · Interfaz visual** ✅ | SPEC-021: temas claro/oscuro/automático con variables y test de contraste, Geist empaquetada, iconos, tarjetas de nodo con puertos en anillo, menú contextual (nodos, conexiones y lienzo), galería de agentes, «En este diagrama», arrastrar desde la paleta, panel inferior con pestañas y paneles plegables, duplicar nodos y quitar conexiones con Supr, Retroceso, menú o botón |
| **M5a · Agentes y ajustes** ✅ | SPEC-022 y SPEC-023: agentes y contextos por proyecto (`.orquestador/agents|contexts`), pantalla «Agentes», «Crear agente» en la galería, ajustes globales con clave API cifrada (`safeStorage`) y paralelismo/límite de tokens por defecto |
| **M5b · Skills e instalación** ✅ | SPEC-024 y SPEC-025: skills por proyecto (`.orquestador/skills/<id>/SKILL.md` + archivos), asignación a agentes, instalar desde carpeta o Zip con revisión previa (límites, zip-slip, avisos de scripts, MCP solo informativo). archivos de referencia por skill (añadir archivos o carpeta, ver, copiar ruta, quitar). SPEC-026 (redactar con Claude) diseñada para M6 |
| **M6a · Motor real de Claude** ✅ | SPEC-027: `packages/claude` (adaptador sobre el Agent SDK, decisiones de enrutado/evaluador, «Probar conexión»), selector de motor simulado/Claude en Ajustes (por defecto simulado), instrucciones, modelo, contextos y skills llegan al agente, solo herramientas de lectura hasta los permisos (R16). Falta probarlo con el SDK real en Electron. Quedan SPEC-026 (redactar con Claude), permisos y espacios por agente |
| **M6b · Pantalla de inicio** ✅ | SPEC-028: sin proyecto abierto la app muestra una pantalla de inicio (crear, abrir, recientes con id opaco y sin rutas absolutas, quitar de la lista, cerrar proyecto) |
| **M6c · Edición asistida** ✅ | SPEC-026 y R22.11–R22.15: «Redactar/Mejorar con Claude» para agentes, skills y contextos de texto (propuesta como borrador con antes/después, nada se guarda hasta Guardar, solo nombres y descripciones hacia Claude); borradores que sobreviven al cambiar de pestaña o elemento con marca de pendiente; editor Markdown alto y ampliable con contador y carga de .md; contextos de archivo con «Elegir archivos/carpeta» (copia al proyecto sin rutas en la interfaz). Pendiente: asistente en chat con herramientas MCP de la app (SPEC-029), instalador asistido por Claude (SPEC-030), MCPs por agente, rediseño del editor (prototipos en curso) |
| **M6d · Editor rediseñado** ✅ | Prototipo A elegido por el usuario: rail de iconos con paneles Nodos (buscador, arrastre), En este diagrama y Plantillas (R21.17–R21.22); selección de skills y contextos del agente en pantalla aparte (R22.16); ventana grande al hacer doble clic en un nodo ejecutado y salidas plegadas (R15.12–R15.13); panel derecho redimensionable (R21.22) |
| **M6e · Carpeta de trabajo** ✅ | SPEC-031 (motor): carpeta de trabajo del proyecto con resumen para los agentes, crear archivos nuevos sin preguntar, modificar existentes preguntando por el chat del nodo (o modo automático en Ajustes), confinamiento a la carpeta, copias y restauración por IPC, preguntas de Claude por el chat. | R31.1–R31.6, R31.9–R31.11 |
| **M6f · Resultados de la carpeta** 🔜 | SPEC-031: archivos creados/modificados en el panel de resultados con diferencias y restaurar; «Carpeta de salida» en el nodo Salida. | R31.7, R31.8 |
| **M5 · Registro y biblioteca** | Alta/configuración de agentes, skills, contextos y catálogo MCP; global vs proyecto con versiones fijables; importación con revisión; optimizar instrucciones con vista de diferencias; plantillas |
| **M6 · Adapter Claude** | Integración con Claude Agent SDK y gestión de secretos |
| **M7 · Replay y pulido** | Reproducción de ejecuciones, empaquetado Windows y Linux |
| **Futuro** | Línea de tiempo, mensajes a agentes en curso, reintentar/saltar nodos, ejecuciones programadas, sidecar Python, plantillas |
